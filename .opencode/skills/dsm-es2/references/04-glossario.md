# Glossário — ES2

## A–C

| Termo | Significado | Observação |
| --- | --- | --- |
| **Abstração** | Focar no essencial, escondendo detalhes | Conceito de OO (aula 03, p. 6) |
| **Agregação** | Associação todo-parte fraca | Losango vazio; a parte sobrevive ao todo |
| **Análise de custo-benefício** | Comparação entre custos e benefícios das alternativas | Parte da viabilidade econômica |
| **Atributo** | O que a classe sabe | Segunda divisão da classe |
| **Classe** | Molde que define atributos e métodos | Retângulo UML |
| **Classe associativa** | Classe que guarda dados de uma associação N:N | Ocorre quando todas as extremidades são `*` |
| **Composição** | Associação todo-parte forte | Losango preenchido; parte exclusiva |
| **Custo de desenvolvimento** | Custo que ocorre uma vez | Pessoal, treinamento, equipamentos |
| **Custo fixo** | Custo recorrente com taxa estável | Aluguel, licença, salários |
| **Custo variável** | Custo proporcional ao uso | CPU, armazenamento, energia |

## D–M

| Termo | Significado | Observação |
| --- | --- | --- |
| **Diagrama de classes** | Diagrama UML que mostra classes e relacionamentos | "Planta baixa" da OO |
| **Escopo** | Limite do que o sistema faz | Não confundir com prazo |
| **Herança** | Relação classe-mãe/classe-filha | Permite polimorfismo |
| **Instanciação** | Criar objeto a partir de uma classe | `new` no código |
| **Métrica de software** | Técnica para medir custo e prazo | Base para contratos |
| **Multiplicidade** | Quantos objetos participam da associação | `0..1`, `1..1`, `*`, `1..*` |
| **Método** | O que a classe faz | Também chamado de operação |

## N–V

| Termo | Significado | Observação |
| --- | --- | --- |
| **Nota UML** | Comentário preso a um elemento | Não altera a estrutura |
| **Ponto de função (PF)** | Medida do tamanho funcional | Mede o "que", não o "como" |
| **Viabilidade** | Estudo para decidir se vale seguir | Quatro tipos |
| **Viabilidade de cronograma** | Os prazos são razoáveis? | Obrigatório × desejável |
| **Viabilidade econômica** | Custo-benefício | "Talvez a mais crítica" |
| **Viabilidade operacional** | Adequação e aceitação pela organização | Envolve o usuário final |
| **Viabilidade técnica** | Tecnologia e conhecimento disponíveis | Curva de aprendizagem impacta prazo |
| **Visibilidade** | Quem acessa um membro da classe | `+`, `-`, `#` |

## Termos ausentes do corpus

- Ator, caso de uso, cenário.
- Diagrama de sequência, atividade, estado.
- Padrão de projeto, arquitetura em camadas.
- Story point, sprint, backlog.
