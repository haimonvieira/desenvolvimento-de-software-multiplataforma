# Glossário — ES1

## A–C

| Termo | Significado | Observação |
| --- | --- | --- |
| **Aceitabilidade** | Software inteligível, útil e compatível com o ambiente do usuário | Atributo de bom software (aula 01, p. 17) |
| **Atividades fundamentais** | Especificação, desenvolvimento, validação e evolução | Aula 01, p. 20 |
| **Cascata (modelo)** | Fases sequenciais com documentos aprovados | Adequado a requisitos estáveis e embarcados |
| **Canvas** | Quadro de 9 blocos para modelo de negócios | Precede o plano de negócios |
| **Canais** | Como o produto chega ao cliente | Bloco do Canvas |
| **Cliente** | Quem compra ou encomenda o software | Pode ser diferente do usuário |

## D–H

| Termo | Significado | Observação |
| --- | --- | --- |
| **Dependabilidade** | Confiabilidade, segurança da informação e safety | Atributo de bom software |
| **Desenvolvimento incremental** | Versões sucessivas com feedback | Atividades intercaladas |
| **Eficiência** | Uso racional de memória e processador | Inclui responsividade |
| **Engenharia de software** | Disciplina de engenharia aplicada à produção de software | Proposta em 1968 |
| **Evolução** | Atividade de mudança após a entrega | Reflete novos requisitos |
| **Fundamentos gerais** | Princípios válidos para todo software | Aula 02, p. 12–15 |

## I–N

| Termo | Significado | Observação |
| --- | --- | --- |
| **Integração e configuração** | Modelo baseado em reuso e configuração | Aula 03, p. 24–29 |
| **Manutenibilidade** | Capacidade de evoluir | Atributo crítico |
| **Modelo de negócios** | Lógica de criação e captura de valor | Antecede o plano |
| **Modelo de processo** | Representação simplificada do processo (SDLC) | Sempre parcial |

## P–R

| Termo | Significado | Observação |
| --- | --- | --- |
| **Plano de negócios** | Documento com etapas, prazos, custos e receitas | Vem depois do modelo |
| **Produto genérico** | Software vendido no mercado para qualquer cliente | Ex.: app, editor de texto |
| **Proposta de valor** | O "que" o negócio oferece | Primeiro bloco do Canvas |
| **Reuso** | Uso de sistemas, componentes ou serviços existentes | Pode ser informal ou formal |
| **SDLC** | Software Development Life Cycle | Sinônimo de modelo de processo |

## S–Z

| Termo | Significado | Observação |
| --- | --- | --- |
| **Sistema embarcado** | Software que controla hardware | Caso típico de cascata |
| **Sistemas de sistemas** | Software composto por outros sistemas | Aula 02, p. 11 |
| **Software personalizado** | Feito sob medida para um cliente | Contrapõe ao genérico |
| **Validação** | Verificar se o software atende ao cliente | Terceira atividade fundamental |
| **Web service** | Serviço remoto reutilizável | Também chamado de API no corpus |

## Termos ausentes do corpus

- Sprint, backlog, Scrum, Kanban.
- Caso de uso, ator, diagrama de classes.
- História de usuário, critério de aceite.
- Story point, velocity.
